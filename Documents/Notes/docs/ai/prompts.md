## 1. Linux 命令笔记生成

**描述**：让 AI 根据命令类型和复杂度，自动生成结构化、统一格式的 Linux 命令笔记。

**Prompt**：

```markdown
写一个 [命令名] 的笔记。

规则：
1. 判断命令类型，选择对应格式
2. 根据命令复杂度决定场景数量（简单命令3个，中等4-5个，复杂6-8个）

类型对应格式：
- 普通命令（grep、ps、df、kill、tar、rsync等）→ 标准格式
- 快捷键工具（vim、htop、tmux、lf）→ 快捷键表格格式
- 配置文件（dae、niri、waybar）→ 配置示例格式
- 包管理工具（pacman、yay、cargo）→ 操作表格格式
- 不确定的类型 → 按标准格式，但会在开头说明

标准格式：
- 一级标题：# [命令名] - 一句话说明
- 开头：一句话理解 + 最常用1-2个例子
- 常用场景：按复杂度决定数量，每个场景一个代码块
- 常用选项速查：三列表格（选项、说明、例子）
- 常见问题：2-3个
- 快捷别名（如果有用）
- 一句话总结

要求：去掉最外层的 ``` 代码块包裹，直接输出 markdown 内容。
```

**使用方式**：将 `[命令名]` 替换为目标命令，直接发给 AI。例：`写一个 grep 的笔记。`

## 2. 通用的“引导式协作提示词”

**描述**：

每次找 AI 帮忙时，把模板粘贴到对话开头

填上具体的任务描述

AI 就会按照你喜欢的节奏一步步带你做

这样无论是找Deepseek、找 ChatGPT、找 Claude，都能获得一致的协作体验。

**Prompt**：

```markdown
我需要你以「引导式协作」模式帮助我完成一个编程任务。

具体要求：
1. 将任务拆解为小步骤，每次只给一步
2. 每一步明确指出：修改哪个文件、在什么位置、添加什么代码
3. 等我执行并贴出代码后，你再检查确认，然后给下一步
4. 每完成一个阶段，跑测试验证，确认无误再继续
5. 不要提前给后续步骤，保持节奏由我控制

现在我要做的任务是：[在此描述你的任务]
```

## 2. 分支决策提示

**描述**：每当完成一个阶段性任务后，如果存在多种合理的下一步选择，用一两句话列出选项并询问我的决定。

**Prompt**：

```markdown
## 当前状态
[一句话描述项目或任务目前进行到了哪一步]

## 可选路径

### 方案 A：[动作名称]
- **具体操作**：[描述]
- **优点**：[描述]
- **缺点/成本**：[描述]

### 方案 B：[动作名称]
- **具体操作**：[描述]
- **优点**：[描述]
- **缺点/成本**：[描述]

### 方案 C：[动作名称]（可选）
- **具体操作**：[描述]
- **优点**：[描述]
- **缺点/成本**：[描述]

## 我的倾向
[给出建议，并说明理由]

## 你的决定
请选择，或提出新的想法。
```

**使用方式**：

```markdown
协作规则：
1. 每次只给一步操作
2. 等我确认后再继续
3. 每完成一个阶段，如果有多个合理的下一步，简短的列出选项并询问我
```

```markdown
## 当前状态
[一句话描述项目目前进行到了哪一步，例如：刚刚完成 Schema 升级，测试已通过]

## 接下来有两个方向，我需要你帮我权衡：

### 方案 A：[动作名称]
- **具体操作**：[例如：继续开发，接入提炼模型]
- **优点**：[例如：能让系统立刻开始"有脑子"，功能连贯]
- **缺点/成本**：[例如：需要花时间设计 Prompt，短期内无法发布]

### 方案 B：[动作名称]
- **具体操作**：[例如：先停一下，发布当前版本]
- **优点**：[例如：立刻有一个可发布的里程碑，获得反馈]
- **缺点/成本**：[例如：下一个版本周期会拉长，功能不完整]

## 我的倾向
[根据你的经验或直觉，给出一个倾向性建议，并解释为什么]

## 你的决定
请选择 A 或 B，或者提出你的新想法。
```
